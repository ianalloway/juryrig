⚖️ juryrig: audit your LLM judge before you trust it

Paste the verdicts/scores your LLM judge already produced and check them for position bias, verbosity bias, calibration and cross-judge agreement, using the real juryrig audit functions running in your browser with Pyodide. Offline, zero keys: your data never leaves this tab and no judge API is called. GitHub · pip install juryrig

Runs juryrig's full audit_suite against five built-in mock judges, each with a deliberate flaw, so you can see what a flagged audit looks like. No input needed.

Input (CSV with header, or a JSON list of objects). One row per pair of responses you showed the judge twice, once in each order:


columnmeaning
case_idoptional label (unique)
verdict_originalwhat the judge said with response X in slot A and Y in slot B: A, B or tie
verdict_swappedwhat it said with the slots swapped (Y in A, X in B): A, B or tie
len_first, len_secondoptional: lengths of X and Y (any unit) for an extra "does the longer answer win?" stat


Verdicts are the judge's literal slot answer. A fair judge's two verdicts are opposite (A→B).

  • What runs here? juryrig's real audit code (v0.3.1 from PyPI), replaying the outputs you paste, inside this browser tab. Live audits that call a judge model (OpenAI, Anthropic, any HTTP endpoint) are available in the library and CLI (juryrig cases.json) but need your own keys, so they are not part of this Space.
    • 
    
  • Privacy: the page only downloads Pyodide (jsDelivr CDN) and the juryrig wheel (PyPI). Pasted data is processed locally and never uploaded.
    • 
    
  • Limits: a flagged audit means the evidence you pasted shows bias at the chosen thresholds; with few cases the numbers are noisy. Defaults are deliberately strict.
    • 
    
  • Disagreement atlas (new in 0.3.1): the Judge agreement tab also ranks the items where the panel splits most, groups items that split the same judge pairs, and shows how often each judge is the contrarian.
